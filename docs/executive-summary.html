Exact submission steps

  1. Gate first: use a file only when the front page explicitly says APPROVED TO SUBMIT. The current H28-3 research files are explicitly ineligible; do not upload them.
  2. Download the approved .tif without opening/re-saving it in GIS software. Keep its content-hashed file name and the short note shown beside it.
  3. Sign in at DrivenData and open the competition page.
  4. Open the submission form (the tab/button label depends on the logged-in view; this project does not automate that site).
  5. Upload the approved single-band .tif – or its approved .zip, which must contain exactly one GeoTIFF – and paste its <=200-character note.
  6. Submit, retain the portal response / score, and record that exact outcome in registry/live_scores.json. Scores stay OWNER-REPORTED unless a receipt is stored.

Submission-format rule for a future approved candidate

The earlier portal message, “Predicted values must be in range [0, 1],” has no established cause because the organizer validator is not public. It is not a reason to upload an unapproved file.

Before any future candidate is labelled approved, the independent validator must record: a single-band float32 GeoTIFF on the exact competition grid/CRS/transform; every in-footprint prediction finite and within [0,1]; an explicitly verified outside-footprint/nodata convention; no known-catalogue overlap where the protocol forbids it; a ZIP containing exactly one TIFF if offered; and a note within the portal limit. The validation receipt and peer-uniqueness result must be linked beside the approved download.
